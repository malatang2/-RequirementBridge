### 实现范围（严格边界——只做这些）

这个工单分三类动作，标注谁能做：

#### 动作一：PostHog key 配置（需要人 + agent 验证）

1. **（需要人）** 去 [PostHog](https://app.posthog.com) 注册/登录，创建一个 Project，获取 Project API key（形如 `phc_xxx`）
2. **（需要人）** 在本地 `.env.local` 加 `NEXT_PUBLIC_POSTHOG_KEY=phc_xxx`（取消 `.env.local.example` 里那行的注释作为提示）
3. **（需要人）** 在 Vercel 项目设置 → Environment Variables 加同样的 `NEXT_PUBLIC_POSTHOG_KEY`
4. **（agent 可做）** 启动 `npm run dev`，打开浏览器登录，用 DevTools Network 面板过滤 `posthog`，确认有请求上报（status 200），证明 key 生效不再静默降级

#### 动作二：Google OAuth provider 配置（需要人 + agent 验证）

1. **（需要人）** 去 [Google Cloud Console](https://console.cloud.google.com) → APIs & Services → Credentials → Create Credentials → OAuth client ID
   - Application type: Web application
   - Authorized redirect URI 填：`<你的-supabase-url>/auth/v1/callback`（supabase-url 在 Supabase 控制台 > Project Settings > API 里）
   - 创建后获取 Client ID 和 Client Secret
2. **（需要人）** 去 Supabase Dashboard → Authentication → Providers → Google，填入 Client ID / Client Secret，启用 provider
3. **（agent 可做）** 启动 `npm run dev`，在登录页点 Google 登录按钮，确认能跳转到 Google 授权页并回跳到 dashboard

#### 动作三：CI 验证（agent 可做大部分）

1. **（agent 可做）** 确认本地 `npm run lint && npm run typecheck && npm run test && npm run build` 四步全绿（这是 CI 会跑的同样四步，本地先验证）
2. **（需要人）** 把当前分支 push 到 GitHub（`git push`）
3. **（agent 可做）** push 后，用 `gh run list` 和 `gh run view` 查看 GitHub Actions 运行状态，确认四步全绿
4. **（agent 可做）** 如果 CI 失败，分析失败原因（常见：lint 规则、typecheck 错误、build 环境变量），修复后重新 push

#### 动作四：Vercel 部署确认

1. **（agent 可做）** 确认 git 工作区干净、最新代码已 commit
2. **（需要人）** 确认 Vercel 已连接 GitHub 仓库且 auto-deploy 开启；push 后 Vercel 会自动部署
3. **（agent 可做）** 部署完成后，访问生产地址（`https://requirement-bridge-8pqp.vercel.app`）确认可访问

### 工作方式要求

- **这个工单不是 TDD 场景**（没有新代码逻辑要测），不要强行套 `/tdd`。它是"配置 + 验证"模式。

- **完成后用 `/code-review` 审查**——虽然这个工单改动少，但如果有任何代码改动（比如取消 .env.local.example 的注释、修 CI 失败），仍需 review。
