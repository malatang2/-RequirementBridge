### 实现导航：照着同文件/跨文件现成模式扩展

#### 扩展点一：createApiDraft 加 source_requirement_id（核心，含越权校验）

仿同文件的现有 createApiDraft 五段式结构，在校验段后加一段 source_requirement 校验：

```typescript
export async function createApiDraft(
  projectId: string,
  input: { businessRequirement?: unknown; apiSpecContext?: unknown; title?: string; sourceRequirementId?: string }
): Promise<ApiDraftActionResult> {
  const validation = validateApiInput(input);
  if (!validation.ok) return { ok: false, error: validation.error };

  const supabase = await createSupabaseActionClient();
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return { ok: false, error: "未登录" };
  if (!projectId) return { ok: false, error: "请先选择项目" };

  // 【05 新增】源需求校验（传入时才校验，越权防护）
  let sourceRequirementId: string | null = null;
  if (typeof input.sourceRequirementId === "string" && input.sourceRequirementId) {
    const { data: srcReq } = await supabase
      .from("requirement_drafts")
      .select("id, project_id, lifecycle, deleted_at")
      .eq("id", input.sourceRequirementId)
      .maybeSingle();
    // 三重校验：存在 + 同项目 + confirmed + 未软删
    if (!srcReq || srcReq.project_id !== projectId || srcReq.lifecycle !== "confirmed" || srcReq.deleted_at !== null) {
      return { ok: false, error: "源需求无效或未确认" };
    }
    sourceRequirementId = srcReq.id;
  }

  // insert 时加 source_requirement_id: sourceRequirementId
  // ... 其余不变
}
```

**越权校验是本工单的安全重点**（工单明确要求"跨项目越权防护"）。RLS 只保证 user_id 隔离，但用户可能传别的项目的 requirement_id——必须显式校验 `project_id === projectId`。

#### 扩展点三：API 新建页加"从需求选择"下拉 + URL query 预填 + 埋点

这是入口 B + 入口 A 的预填承接点。三个改动：

1. **URL query 预填**（入口 A 承接）：
   ```tsx
   import { useSearchParams } from "next/navigation";
   // ...
   const searchParams = useSearchParams();
   const queryReqId = searchParams.get("requirementId");
   ```

2. **"从需求选择"下拉**（入口 B）：需要客户端拉 confirmed Requirement 列表。两种实现：
   - **方案 A（推荐，简单）**：在新建页用 `useEffect` + supabase 客户端 client 拉 `requirement_drafts` where lifecycle='confirmed' + deleted_at is null。仿 feedback 模块或 meetings 模块的客户端查询写法。
   - 方案 B：加个 server action `listConfirmedRequirements(projectId)`。但新建页已经是客户端组件，直接用客户端 client 更顺。
   - 选方案 A。下拉选中或 URL query 命中时，把选中 Requirement 的 title + content 预填到 title + businessRequirement 字段。

3. **埋点**：在 handleSubmit 创建成功后加 `track("requirement_to_api_triggered", { requirement_id: sourceRequirementId, draft_id: result.draftId })`。注意只在 `sourceRequirementId` 非空时触发（手动新建不带 source 的不触发这个埋点）。`track` 已在文件顶部 import（看现有代码 `await track("api_generation_started", ...)`）。
