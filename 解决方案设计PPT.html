业务问题 / 03
PROBLEM · 解决什么问题

当前产研协作的四大痛点

从"会议决策"到"可执行任务/接口"，链路割裂、靠人工搬运、偏差在后期才暴露。

🎤 会议侧

  • 录音/笔记散落，关键决策易遗漏
  • 纪要人工整理耗时、标准不一
  • 待办负责人不明，无人跟进

🔌 需求转技术侧

  • PM 写自然语言 PRD
  • 研发凭理解手写接口
  • 偏差在联调才暴露 → 返工

💬 反馈侧

  • 多渠道反馈分散，逐条阅读成本高
  • 聚类/频次/情感靠人工估算
  • 优先级主观，难横向比较

🔗 横向割裂

  • 三环节彼此孤立
  • 无"会议→需求→接口"贯通链路
  • 数据需人工搬运

⚠️ 问题本质：这不是单点工具缺失，而是"决策 → 执行"全链路缺少结构化沉淀——会议结论无法直接变成可执行需求，需求无法直接变成可对接接口，反馈无法直接变成可排序的需求池。

来源：《需求说明清单 v0.1》§3 当前业务问题（AS-IS 痛点）。

方案总览 / 04
SOLUTION OVERVIEW · 解决思路

一座"需求桥"，AI 一次性结构化

三大模块各管一段，统一以"AI 结构化 + 人确认 + 导出"为价值闭环，v1 以单用户 + 项目为边界。

👤 散点输入
会议音频/笔记、业务需求、多渠道用户反馈——原本分散在各工具的原始素材
→
🤖 AI 结构化
通义千问 + Paraformer：转录、提取、生成、聚类——把非结构化内容变成结构化产出
→
✏️ 人确认校对
所有 AI 产出默认可编辑/增删/改优先级——AI 不自主写副作用，决策权在人
→
📤 导出落地
Markdown / CSV / YAML / JSON / PNG——结构化产出外溢到团队既有流程

🎤 模块一·会议纪要

音频/文本 → 转录 + 结构化提取【决策/待办/需求/问题】，带负责人、优先级、原文引用。

🔌 模块二·API 设计器

业务需求 → 生成 OpenAPI 3.0 草稿（camelCase + 错误码 + Schemas），代码/可视化双视图。

💬 模块三·反馈洞察

多渠道反馈 → 主题聚类 + 情感 + 频次 + 优先级，一键生成需求草稿回灌主链路。

设计原则：人定方向、做确认；AI 做结构化与生成；系统做存取与上报。v1 三模块相互独立，串联由人主导（手动），端到端自动流水线留 v2。

项目范围 / 06
OUT OF SCOPE · 本阶段不做什么

v1 明确不做——边界清晰才能交付

不做的是为避免范围蔓延与过度设计；每一项都有明确的"留 v2"或"默认值"处置。

🚫 不做团队级多人协作

v1 以"单用户 + 项目"为边界（Supabase RLS 限定本人数据）。不支持成员角色、共享编辑、评论 @、权限分级。

🚫 不做第三方系统实时集成

不直连 Jira/飞书/钉钉/Linear/Swagger/Postman；产出仅通过导出文件（MD/CSV/YAML/JSON/PNG）和剪贴板外溢。

🚫 不做 API Mock/SDK/版本 Diff

仅生成与展示 OpenAPI 定义，不提供请求调试、Mock 返回、代码生成、版本对比。版本仅保存。

🚫 不做反馈渠道直采

不直接对接客服系统/NPS 平台/应用商店评论 API，需用户手动粘贴或上传文件。

🚫 不做 AI 自主执行

无 Agent 自主写入外部系统。AI 仅做转录/提取/生成/聚类，所有落地动作由人确认与导出。

🚫 不做端到端自动串联流水线

v1 三模块相互独立，不自动把"会议需求"喂给"API 设计器"。串联由人主导（手动"带入"按钮）。

音视频多模态/说话人分离：v1 仅语音转文本 + 文本结构化，不区分发言人。

私有化/本地大模型：统一走阿里云通义千问，不做本地部署。

反馈增量分析：v1 为一次性分析，不追加到已有任务。

来源：《SOW》§3、《需求说明清单》§5。取舍原则：单用户价值闭环优先，团队协作/实时集成/自动化留 v2。

USER FLOW · 模块一 会议纪要

模块一：会议决策一键结构化

改善环节：把"人工整理纪要 + 待办无人跟进"变成"AI 转录提取 + 人只做校对"。

→
2️⃣ AI 转录+提取
Paraformer 转录 → Qwen 提取【决策/待办/需求/问题】+ 摘要 + 负责人/优先级/原文引用
→
3️⃣ 校对编辑

  • 纪要整理：人工 → AI 一次完成

模块三：反馈聚类量化，一键生成需求

改善环节：把"逐条人工阅读 + 主观估算优先级"变成"AI 聚类量化 + 可追溯的优先级建议"。
