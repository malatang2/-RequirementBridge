## 1. 项目目标（Objectives）

### 1.1 业务目标
把产品经理手中**散点式的会议决策与多渠道用户反馈**，高效转化为**结构化的产品需求**，并进一步精准转化为**可执行的技术需求（OpenAPI 草稿）**，降低产研沟通成本与返工。

### 1.2 交付目标（可衡量）
- **三模块可用**：会议纪要、API 设计器、反馈洞察三大模块在 v1 范围内**端到端可走通**（输入 → AI 处理 → 人校对 → 落库 → 导出）。
- **AI 准确度达标**：见 §6 验收标准（结构化提取、OpenAPI 生成、反馈聚类有基本准确度门槛）。
- **单用户价值闭环**：v1 以"单用户 + 项目"为边界（Supabase RLS 限定本人数据），跑通"上传 → 结构化 → 校对 → 导出"全链路。
- **可演示 Demo**：Day 6（2026-08-01）前，三大模块各产出可演示的核心链路 Demo。

### 1.3 非目标（明确不在本期达成）
- 团队级多人协作、第三方系统实时集成、自动串联流水线、私有化部署——详见 §3 范围外。

## 2. 交付范围（In Scope）

### 2.1 模块一：智能会议纪要与任务提取（`/dashboard/meetings`）
- **输入**：上传音频（mp3/wav/m4a，≤50MB）或粘贴文本。
- **AI 流程**：fun-asr/Paraformer 转录 → Qwen-Max 结构化提取【决策 / 待办 / 需求 / 遗留问题】，含负责人、优先级、原文引用、整体摘要。
- **结果**：按类型分组展示，全条目可编辑/删除/改优先级/改负责人，支持手动新增。
- **导出**：Markdown、CSV、复制到剪贴板。

### 2.2 模块二：业务需求 → API 草稿生成（`/dashboard/api-designer`）
- **输入**：业务需求描述（必填）+ API 规范上下文（选填）。
- **AI 流程**：Qwen-Max 生成 **OpenAPI 3.0 YAML**（路径/方法/参数/响应/Schemas/认证/错误码，camelCase）。
- **结果**：代码视图（高亮 + 可编辑 + 实时 YAML 校验）与可视化视图（Swagger 风格卡片）；支持重新生成、版本保存、版本历史。
- **导出**：YAML、JSON（OpenAPI）、复制。

### 2.3 模块三：智能用户反馈洞察（`/dashboard/feedback`）
- **输入**：粘贴文本（每条换行）或上传 CSV/TXT（CSV 需指定反馈列）。
- **AI 流程**：Qwen-Plus 做**主题聚类 / 命名 / 摘要 / 频次 / 情感 / 优先级建议 / 样本反馈**。
- **结果**：统计卡片（总数/主题数/高优数/负面占比）、横向条形图、情感饼图、可折叠主题卡（可编辑/合并/删除）。
- **衍生**：勾选主题 → 生成需求草稿（可编辑、可导出）。
- **导出**：Markdown 报告、CSV 主题、PNG 图表、复制。

### 2.4 通用与平台
- **通用**：Landing Page、邮箱/Google OAuth 登录、Dashboard 布局（项目选择器 + 三模块导航 + 设置/登出）、项目 CRUD、Light/Dark、响应式、Toast、表单校验、AI 过程 loading 文案。
- **埋点与 SEO**：PostHog（自定义事件 + pageview）、GA4、SEO（meta / sitemap / robots / 预留百度与 GSC 验证）。
- **技术底座**：Next.js(App Router, TS) + Tailwind + shadcn/ui + Supabase(Postgres/Auth/Storage/Edge Functions) + **阿里云百炼/DashScope（通义千问 Qwen + fun-asr/Paraformer）** + Vercel，支付预留 Stripe。【CP0：由 OpenAI 迁移至通义千问，国内不出境，合规/成本/中文质量三赢】
- **非功能**：异步处理 + 进度提示（status 状态机：uploading/transcribing/analyzing/completed/failed）、全表 RLS、HTTPS、`.env.local` 统一环境变量。

## 3. 范围外（Out of Scope）

> 以下为 **v1 明确不做**，需在评审中确认是否纳入 v2 路线图。本 SOW 不为其投入排期。

1. **不做团队级多人协作**：v1 以"单用户 + 项目"为边界（RLS 限定本人数据），不支持成员角色、共享编辑、评论 @、权限分级。
2. **不做与第三方系统的实时双向集成**：不直连 Jira / 飞书 / 钉钉 / Linear / Swagger / Postman；产出仅通过**导出文件（MD/CSV/YAML/JSON/PNG）**和剪贴板外溢。
3. **不做 API 草稿的实时预览联调 / Mock Server / SDK 生成**：仅生成与展示 OpenAPI 定义，不提供请求调试、Mock 返回、代码生成。
4. **不做反馈的渠道直采**：不直接对接客服系统/NPS 平台/应用商店评论 API，需用户手动粘贴或上传文件。
5. **不做事由 AI 自主执行任务**（无 Agent 自主写入外部系统）：AI 仅做"转录 / 提取 / 生成 / 聚类"，所有落地动作由人确认与导出。
6. **不做三大模块的自动串联流水线**：v1 三大模块相互独立，不自动把"会议需求"喂给"API 设计器"或把"反馈主题"喂给需求池（手动串联）。
7. **不做音视频多模态分析与说话人分离（Diarization）**：v1 仅做语音转文本与文本结构化，不区分发言人、不分析语气情绪。
8. **不在 v1 做私有化/本地大模型部署**：统一走**通义千问 DashScope**云托管 API（国内不出境）。【CP0：由 OpenAI 迁移】
9. **不做 API 草稿版本 Diff / 反馈增量分析**（v1 为一次性分析、版本仅保存）。

## 4. 关键假设（Assumptions）

1. 用户具备基本的产品/技术语境，能判断 AI 产出的准确性并完成校对。
2. 通义千问/DashScope API（Qwen + fun-asr/Paraformer）可用性、延迟、价格在可接受范围；key 由部署方提供（百炼控制台开通）。【CP0：由 OpenAI 迁移】
3. 单用户场景足以验证价值，**团队协作非 MVP 必需**。
4. 各模块的输出**以"人确认 + 导出"为终点**，企业系统对接以离线文件为主。
5. 输入语料以**中文**为主，少量英文；Qwen/fun-asr 对中文会议与反馈的理解质量达标（中文原生优化）。
6. 用户接受将相关数据上传至 Supabase 与阿里云百炼/DashScope（国内区域）处理。
7. 三大模块在 v1 **相互独立**，不强制端到端串联。

## 6. 验收标准（Acceptance Criteria）

> 验收分两层：**§6.1 功能验收**（功能可用，对照源需求一一对齐）与 **§6.2 准确度基本要求**（AI 产出质量门槛）。准确度门槛为"基本要求"，达标即视为功能合格，未达视为缺陷需修复。

### 6.1 功能验收（必须全部满足）

#### 模块一·会议纪要
- 音频（mp3/wav/m4a，≤50MB）与粘贴文本两种入口均可发起分析。
- 全过程有 status 进度提示（uploading/transcribing/analyzing/completed/failed），失败有明确提示与可重试。
- 结构化条目按【决策 / 待办 / 需求 / 遗留问题】四类分组展示，含整体摘要。
- 每条条目可编辑/删除/改优先级/改负责人/手动新增；条目带原文引用。
- 可导出 Markdown、CSV，可复制到剪贴板。
- 仅本人可见（RLS 生效）。

#### 模块二·API 设计器
- 业务需求（必填）+ API 规范上下文（选填）可发起生成。
- 产出 OpenAPI 3.0 YAML：含路径/方法/参数/响应/Schemas/认证，错误码至少含 400/401/404/500，字段 camelCase。
- 代码视图（高亮 + 可编辑 + 实时 YAML 校验）与可视化视图（Swagger 风格卡片）双视图可用。
- 支持重新生成、版本保存、版本历史。
- 可导出 YAML、JSON（OpenAPI），可复制。

#### 模块三·反馈洞察
- 粘贴文本（每条换行）与上传 CSV/TXT（CSV 指定反馈列）两种入口均可发起分析。
- 产出统计卡片（总数/主题数/高优数/负面占比）、横向条形图（按 frequency 降序）、情感饼图、可折叠主题卡。
- 主题卡支持编辑/合并/删除；每主题含 2-3 条样本反馈。
- 勾选主题可生成需求草稿（可编辑、可导出）。
- 可导出 Markdown 报告、CSV 主题、PNG 图表，可复制。

#### 通用与平台
- Landing / 邮箱登录 / Google OAuth 可走通；Dashboard 布局含项目选择器 + 三模块导航 + 设置/登出。
- 项目 CRUD 可用；Light/Dark 切换；移动端响应式（侧栏可折叠）。
- Toast 反馈、表单前端校验、AI 过程 loading 文案齐备。
- PostHog（自定义事件 + pageview）、GA4、SEO 基础项就位。

### 6.2 准确度基本要求（AI 产出质量门槛）

> 采用"**固定评测集 + 人工抽检**"双重验证。每模块准备一份小规模评测集（建议各 10-20 条样本），按下列门槛达标即合格；连续 3 批不达标须回查 Prompt 与链路。

| 模块 | 指标 | 基本要求（门槛） | 验证方式 |
|---|---|---|---|
| 模块一·会议 | **结构化分类准确率**（决策/待办/需求/问题 四类分对） | ≥ 80% | 评测集人工标注对比 |
| 模块一·会议 | **负责人/优先级抽取命中率**（有人结论时） | ≥ 70% | 评测集抽检 |
| 模块一·会议 | **原文引用可追溯率**（引用文字确实出现在转录文本中） | ≥ 90% | 程序化校验引用片段是否存在 |
| 模块一·会议 | **转录可读性**（fun-asr/Paraformer 中文转写，关键字段无大面积错译） | 主观评分 ≥ 4/5（多数样本可被 PM 直接校对采用） | 人工抽检 10 条 |
| 模块二·API | **OpenAPI 合法率**（生成的 YAML 能通过 OpenAPI 3.0 Schema 校验） | 100%（不合法即视为缺陷） | 程序化 YAML + Schema 校验 |
| 模块二·API | **字段命名规范率**（camelCase、无命名冲突） | ≥ 95% | 程序化扫描 + 抽检 |
| 模块二·API | **错误码完整率**（至少含 400/401/404/500） | 100% | 程序化校验 |
| 模块二·API | **语义相关度**（生成的接口与业务需求意图相符） | 主观评分 ≥ 4/5 | 人工抽检 10 条 |
| 模块三·反馈 | **聚类合理度**（同主题反馈语义一致、异主题可区分） | 主观评分 ≥ 4/5 | 人工抽检 |
| 模块三·反馈 | **频次统计准确率**（各主题 feedback 数量与实际归入一致） | 100% | 程序化核对 |
| 模块三·反馈 | **情感分类一致率**（正/负/中性与人工判断一致） | ≥ 75% | 评测集抽检 |
| 模块三·反馈 | **样本代表性**（每主题 2-3 条样本确实代表该主题） | ≥ 90% 主题达标 | 人工抽检 |

> **统一规则**：
> - **程序化可校验项**（YAML 合法、camelCase、错误码、频次、原文引用）**必须 100% 或门槛达标**，不达标即缺陷，须在当日内修复。
> - **主观评分项**采用 5 分制，由 PM（或产品负责人）抽检打分；≥ 4/5 视为达标。
> - 评测集与抽检记录留档，作为验收依据。

## 7. 工作方式与协作约定

- **节奏**：以 Day 为单位推进（Day 2-6 为本 Sprint），每日有明确里程碑与截止时间（见排期文档）。
- **AI 链路优先**：Day 2-3 优先打通"输入 → DashScope → 结构化产出"的最小闭环，再做前端展示与导出。
- **"人确认 + 导出"边界**：所有 AI 产出默认可被人工编辑/校对，落地动作不自动写外部系统。
- **环境与密钥**：DashScope key、Supabase 配置统一走 `.env.local`，不入库不入仓。
- **状态机**：长任务一律走 status 状态机（uploading/transcribing/analyzing/completed/failed），前端不阻塞。
- **变更**：范围变更须更新 SOW §2/§3 与排期文档，并重新评审。

## 8. 风险与缓解（摘要）

| 风险 | 影响 | 缓解 |
|---|---|---|
| AI 准确度不达标 | 模块可用但价值打折 | 评测集驱动 + Prompt 迭代；不达标当日修复 |
| AI 服务延迟/成本 | 体验与成本 | 异步处理 + 进度提示；DashScope 国内定价更低 + 免费额度（C1） |
| 数据合规（音频/反馈送 DashScope） | 合规/售卖 | **CP0 已化解**：迁通义千问国内不出境即满足基线；v1 加上传前提示 + 敏感字段建议（B8） |
| 5 个工作日交付密度 | 排期紧张 | 模块独立并行；Day 2-3 打通 AI 闭环，Day 4-5 接前端，Day 6 Demo |
