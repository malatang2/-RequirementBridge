## 1. 功能模块拆解与优先级

### 1.1 模块结构（WBS 一级 / 二级）

```
RequirementBridge v1
├── M0 平台底座与通用（基础设施，先行）
│   ├── 数据模型与 RLS（Supabase Postgres）
│   ├── Auth（邮箱 + Google OAuth）
│   ├── Dashboard 骨架（项目选择器 + 导航 + 布局）
│   ├── 项目 CRUD
│   └── 工程规范（目录 / env / OpenAI 封装 / 状态机）
├── M1 模块一·智能会议纪要与任务提取（/dashboard/meetings）
│   ├── 输入（音频上传 / 文本粘贴）
│   ├── AI 链路（Whisper 转录 + GPT-4o 结构化提取）
│   ├── 展示与编辑（四类分组 / 编辑 / 增删 / 摘要）
│   └── 导出（MD / CSV / 复制）
├── M2 模块二·业务需求 → API 草稿生成（/dashboard/api-designer）
│   ├── 输入（业务需求 + API 规范上下文）
│   ├── AI 链路（GPT-4o 生成 OpenAPI 3.0 YAML）
│   ├── 双视图（代码视图 + 可视化卡片 / YAML 校验）
│   ├── 版本管理（保存 / 历史 / 重新生成）
│   └── 导出（YAML / JSON / 复制）
├── M3 模块三·智能用户反馈洞察（/dashboard/feedback）
│   ├── 输入（粘贴 / 上传 CSV·TXT）
│   ├── AI 链路（聚类 / 命名 / 摘要 / 频次 / 情感 / 优先级 / 样本）
│   ├── 展示与编辑（统计卡 / 条形图 / 饼图 / 主题卡 / 合并·删除）
│   ├── 需求草稿（勾选主题 → 生成草稿）
│   └── 导出（MD / CSV / PNG / 复制）
└── M4 横切能力（贯穿各模块）
    ├── UI/UX（Light/Dark、响应式、Toast、表单校验、loading）
    ├── 埋点与可观测（PostHog / GA4 / status 落库）
    └── SEO（meta / sitemap / robots / 百度·GSC 预留）
```

### 1.2 优先级总览

| 优先级 | 含义 | 本 Sprint（Day 2-6）目标 |
|---|---|---|
| **P0** | Day 6 可演示 Demo 必须 | 三大模块各打通"输入 → AI → 展示 → 导出"核心链路 |
| **P1** | 本 Sprint 应交付 | 版本管理、合并/删除、统计图表、埋点、响应式、Dark |
| **P2** | 可后置到后续阶段 | SEO 细项、用量看板、百度/GSC 验证、Stripe 联调 |

## 2. 模块依赖关系

### 2.1 依赖图

```
D0 设计阶段（数据模型 / 接口契约 / UI 线框）── 最前置，冻结后开发才有依据
   │  （v1.1 已完成三份产物，Day 2 上午评审冻结）
   ▼
M0 平台底座（Auth/Dashboard/工程规范/按 D0 落库建表/RLS）
   │
   ├──► M1 会议（依赖：Storage 音频、OpenAI 封装、status 状态机、meetings 表）
   ├──► M2 API（依赖：OpenAI 封装、api_drafts 表）          ← 与 M1/M3 可并行
   └──► M3 反馈（依赖：Storage 文件、OpenAI 封装、feedback_* 表）

M4 横切能力 ── 贯穿：UI 组件 / 埋点 / 导出 工具在各模块复用
   │
   └──► 集成联调（M1+M2+M3 + M4 汇总）──► 验收 ──► 上线
```

### 2.2 关键依赖约束（决定排期）

| 上游 | 下游 | 约束 |
|---|---|---|
| **D0-数据模型设计** | M0-建表 + M1/M2/M3 | **DDL/RLS 已产出（v1.1）**；Day 2 上午评审冻结后，下午按 DDL 建表，避免边开发边改表 |
| **D0-接口契约** | M1/M2/M3 Edge Function + 前端 | **入参/出参/错误码/状态机已产出（v1.1）**；前后端据此并行 |
| **D0-UI 线框** | 各模块前端 | **页面结构与交互已产出（v1.1）**；前端开发有依据，不再临时拍脑袋 |
| M0-数据模型/RLS | M1/M2/M3 全部 | 表结构未定，模块无法落库 → **Day 2 必须完成**（按 D0 落地） |
| M0-OpenAI 封装 | M1/M2/M3 AI 链路 | 封装未定，三模块重复造轮 → **Day 2 必须完成** |
| M0-status 状态机 | M1（音频异步） | 长任务前端不阻塞的前提 → **Day 2 完成骨架** |
| M1-AI 链路 | M1-展示/导出 | 先打通"输入→结构化产出"，再做前端 |
| M2-AI 链路 | M2-双视图 | YAML 生成稳定后，再做代码/可视化视图 |
| M3-AI 链路 | M3-图表/需求草稿 | 聚类产出稳定后，再做图表与草稿回灌 |
| 各模块完成 | 集成联调 | 三模块独立可跑后才能端到端联调 |

> **并行策略**：D0 冻结后，M0 当天落地；M0 完成后，M1 / M2 / M3 三条线可并行推进；AI 链路（Prompt + Edge Function）优先于前端展示。
>
> **v1.1 关键收益**：设计产物前置，把原本"边开发边定表/定接口/定交互"的隐性返工，前移到 Day 2 上午一次性冻结。

## 4. 准确度验收清单（与 SOW §6.2 对齐，可执行版）

> 验证方式分两类：`[程序]` = 可程序化校验（必须达标，否则缺陷）；`[人工]` = PM 抽检 5 分制（≥4 达标）。

### 4.1 模块一·会议

| 检查项 | 方式 | 门槛 | 责任 |
|---|---|---|---|
| 结构化分类准确率（四类分对） | [人工] 评测集 10-20 条 | ≥ 80% | PM + 研发 |
| 负责人/优先级抽取命中率 | [人工] 抽检 | ≥ 70% | PM |
| 原文引用可追溯率（引用片段确实在转录文本中） | [程序] 字符串包含校验 | ≥ 90% | 研发 |
| 转录可读性（Whisper 中文） | [人工] 抽检 10 条，5 分制 | ≥ 4/5 | PM |

### 4.2 模块二·API

| 检查项 | 方式 | 门槛 | 责任 |
|---|---|---|---|
| OpenAPI 合法率（YAML 通过 3.0 Schema 校验） | [程序] Swagger Parser 校验 | **100%** | 研发 |
| 字段命名规范率（camelCase、无冲突） | [程序] 扫描 + 抽检 | ≥ 95% | 研发 |
| 错误码完整率（含 400/401/404/500） | [程序] 校验 | **100%** | 研发 |
| 语义相关度（接口与业务需求相符） | [人工] 抽检 10 条，5 分制 | ≥ 4/5 | PM |

### 4.3 模块三·反馈

| 检查项 | 方式 | 门槛 | 责任 |
|---|---|---|---|
| 聚类合理度（同主题一致、异主题可分） | [人工] 抽检，5 分制 | ≥ 4/5 | PM |
| 频次统计准确率（主题数=实际归入数） | [程序] 核对 | **100%** | 研发 |
| 情感分类一致率（正/负/中与人工一致） | [人工] 评测集抽检 | ≥ 75% | PM |
| 样本代表性（每主题 2-3 条样本代表该主题） | [人工] 抽检 | ≥ 90% 主题达标 | PM |

> **统一规则**：`[程序]` 项不达标 = 缺陷，须当日内修复；`[人工]` 项连续 3 批不达标须回查 Prompt 与链路。
