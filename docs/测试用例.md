## 三、测试用例详情（含前置条件与执行步骤）

### TC-01 邮箱密码登录
- **前置条件**：测试账号已注册且邮箱已确认
- **执行步骤**：POST `/auth/v1/token?grant_type=password`，body 含正确 email + password
- **预期**：HTTP 200，响应含 `access_token` / `refresh_token`
- **实际**：HTTP 200，access_token 已返回

### TC-02 错误密码登录
- **前置条件**：账号存在
- **执行步骤**：POST `/auth/v1/token?grant_type=password`，password=`WrongPass!`
- **预期**：非 200，返回错误
- **实际**：HTTP 400，拒绝

### TC-03 音频超过 50MB
- **前置条件**：纯函数 `validateAudioFile`
- **执行步骤**：`validateAudioFile({size: 52428801, ...})`
- **预期**：`{ok:false, error:"超过 50MB"}`
- **实际**：size > 52428800，校验拒绝

### TC-04 音频刚好 50MB
- **执行步骤**：`validateAudioFile({size: 52428800, ...})`
- **预期**：`{ok:true}`
- **实际**：未超限，放行

### TC-05 未登录访问受保护数据
- **执行步骤**：GET `/rest/v1/projects?select=id`，仅带 anon key，无 Authorization
- **预期**：HTTP 200，返回 `[]`（0 行）
- **实际**：HTTP 200，0 行

### TC-06 伪造 user_id 越权写入
- **前置条件**：已登录用户 A（持有 A 的 token）
- **执行步骤**：POST `/rest/v1/projects`，body 含 `user_id = 00000000-...`（非本人）
- **预期**：RLS `with check (user_id = auth.uid())` 拒绝
- **实际**：HTTP 403

### TC-07 调用不存在的 Edge Function
- **执行步骤**：POST `/functions/v1/non-existent-fn`
- **预期**：非 200，系统返回错误
- **实际**：HTTP 404

### TC-08 空项目名创建
- **执行步骤**：POST `/rest/v1/projects`，`{name:""}`
- **预期**：业务校验拦截
- **实际**：DB 层 `name text not null` 允许空串（HTTP 201）；前端 `validateProjectInput` 已拦截空名 → **已知问题 K-1**（建议 v2 加 DB check 约束）；测试数据已清理

### TC-09 会议结构化提取端到端
- **前置条件**：已建 meeting 记录（status=analyzing）
- **执行步骤**：调 `meeting-extract` EF，输入含 4 类要点的文本
- **预期**：提取 ≥4 条，`quote_offset` 命中率 ≥90%，status→completed
- **实际**：提取 4 条，追溯 4/4=100%，status=completed

### TC-10 编辑条目触发 is_edited 联动
- **前置条件**：meeting_item 存在
- **执行步骤**：UPDATE meeting_item 的 content
- **预期**：触发器 `trg_mark_meeting_edited_update` 把 meeting.is_edited 置 true
- **实际**：meeting.is_edited = true

### TC-11 跨项目数据隔离
- **前置条件**：用户有项目 A、项目 B
- **执行步骤**：分别在 A、B 建数据，对比 project_id
- **预期**：A 的数据 project_id ≠ B，互不可见
- **实际**：A.project_id ≠ B，隔离生效

### TC-12 用户反馈聚类端到端
- **前置条件**：已建 feedback_analyses + feedback_items
- **执行步骤**：调 `feedback-analyze` EF，输入 8 条多类反馈
- **预期**：主题 ≥3，frequency 与 items 计数一致，status→completed
- **实际**：4 主题，频次一致 100%，status=completed
