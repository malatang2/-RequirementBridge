## 五、失败原因、优化前后变化与已知问题

### 5.1 评测过程中发现并修复的问题

| # | 问题 | 原因 | 优化前 | 优化后 |
|---|---|---|---|---|
| F-1 | API 生成 a1 错误码不完整 | Qwen-Max 偶发漏生成某错误码 | 缺 400/401/404/500 之一（评测 FAIL） | **加强 Prompt**（"绝对强制，一个都不能少"）+ 服务端校验重试 → 稳定 100% |
| F-2 | API 生成 a2 缺 openapi 字段 | 模型输出 `\`\`\`yaml` 包裹，清理逻辑不健壮 | 清理后 `^openapi:` 未匹配（误判 FAIL） | **健壮化 YAML 清理**（trim + 多行匹配） → 正确识别 |
| F-3 | 频次触发器跨主题 BUG（CP0 #1a②） | UPDATE 移动 item 时只刷新新主题 | 旧主题 frequency 虚高（违反 100%） | **修复触发器**（同时刷新 old+new） → 频次 100% 一致 |

### 5.2 已知问题（不阻断上线，纳入后续迭代）

| # | 问题 | 影响 | 处置 |
|---|---|---|---|
| **K-1** | DB 层允许空字符串项目名（`name text not null` 不拒绝空串） | 用户可能通过 API 直建空名项目（前端已拦截，但 API 层未拦） | **前端 `validateProjectInput` 已拦截**；建议 v2 加 DB check 约束 `check (length(trim(name)) > 0)` |
| K-2 | PostHog key 未配置 | 埋点事件不上报（静默降级，不影响功能） | 代码就位，配 key 即启用；v1 可选 |
| K-3 | Google OAuth 未配置 provider | Google 登录按钮不可用 | 需在 Supabase Auth 配置 Google OAuth；邮箱登录已可用 |
| K-4 | Edge Function 单次执行时长（150s）对大音频有风险 | 接近上限的音频可能超时 | 已有降级（asr_task_id 断点续查 + 前端轮询）；v1 接受 |
| K-5 | Vercel 未连接部署 | 无预发布环境 | 代码 build 通过，连仓库即可 |
