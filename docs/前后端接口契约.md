## 0. 总体约定

### 0.1 通信方式分层

| 类型 | 通道 | 用途 |
|---|---|---|
| **数据 CRUD** | Supabase JS SDK 直连（RLS 保护） | 列表/详情/编辑/删除等常规操作，前端直接读写表 |
| **AI 长任务** | Supabase **Edge Function**（Deno） | 转录、结构化提取、生成 OpenAPI、聚类——涉及 **DashScope key**，必须服务端 |
| **文件上传** | Supabase **Storage SDK** | 音频/反馈文件，前端直传签名 URL |
| **导出** | 前端纯计算 + Edge Function（仅 PNG 图表需服务端渲染时） | MD/CSV/YAML/JSON 前端生成；PNG 视情况 |
| **实时进度** | 前端**轮询** `status` 字段（v1 不引入 Realtime） | 长任务进度提示 |

> **原则**：**DashScope key 绝不进前端**；一切涉及密钥的调用走 Edge Function。数据 CRUD 走 SDK + RLS，无需自建 REST。
> **网络方案（CP0 B5）**：v1 用 Supabase Edge Function（Day 2 实测 DashScope 连通性）；不达标则 AI 调用层迁阿里云 FC——封装层抽象 `LLMProvider` 接口预留切换。

### 0.2 请求与响应格式

- **Edge Function 统一响应**（JSON）：
  ```json
  {
    "success": true,
    "data": { ... },
    "error": null
  }
  ```
  失败时：
  ```json
  {
    "success": false,
    "data": null,
    "error": {
      "code": "LLM_TIMEOUT",
      "message": "AI 服务调用超时，请重试",
      "details": { "retryable": true }
    }
  }
  ```
- **鉴权**：所有 Edge Function 通过请求头 `Authorization: Bearer <supabase_access_token>`，服务端用 `supabase.auth.getUser()` 校验，**用 user_id 作为所有写入的归属**（前端无法伪造，因 RLS 双重保护）。
- **CORS**：Edge Function 返回 `Access-Control-Allow-Origin` 允许前端域名。
- **幂等性**：所有写操作以数据库记录 ID 为幂等键；前端重试同一请求时携带同一 `client_request_id`（UUID，可选）。

### 0.3 统一错误码表

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `UNAUTHORIZED` | 401 | 未登录或 token 失效 | 跳转登录 |
| `FORBIDDEN` | 403 | RLS 拒绝（非本人数据） | 提示无权限 |
| `VALIDATION_ERROR` | 422 | 入参校验失败 | 表单内联错误 |
| `NOT_FOUND` | 404 | 资源不存在 | 404 页 |
| `FILE_TOO_LARGE` | 413 | 音频 >50MB | 上传前拦截 + 提示 |
| `UNSUPPORTED_FORMAT` | 415 | 非 mp3/wav/m4a | 表单提示 |
| `LLM_TIMEOUT` | 504 | AI 服务调用超时 | 可重试 |
| `LLM_RATE_LIMIT` | 429 | AI 服务限流 | 提示稍后重试 |
| `LLM_ERROR` | 502 | AI 服务返回错误 | 记录 + 可重试 |
| `GENERATION_FAILED` | 500 | 生成/分析失败（业务层） | 落库 status=failed，提示重试 |
| `INTERNAL_ERROR` | 500 | 未知异常 | Toast 错误 + 上报 PostHog |

> 前端根据 `error.details.retryable` 决定是否显示"重试"按钮。
>
> **CP0：DashScope 错误码 → 统一错误码映射**（封装层 T0.5 须显式归一化，否则前端 retryable 判断会错）：

| DashScope 实际返回 | 映射到 | retryable | 说明 |
|---|---|---|---|
| HTTP 429 / `Throttling`（限流） | `LLM_RATE_LIMIT` | true | 稍后重试 |
| 请求超时 / 网络不通 | `LLM_TIMEOUT` | true | 可重试 |
| `InvalidApiKey` / `AccessDenied` | `LLM_ERROR` | false | key 配置问题，不可自动恢复 |
| 模型返回非法 JSON / 内容截断 | `GENERATION_FAILED` | true | 服务端兜底解析 + 重试 1 次 |
| Paraformer 任务状态 `Task Failed` | `GENERATION_FAILED` | true | 转写任务失败，可重试 |
| 其他 4xx/5xx | `LLM_ERROR` | false | 记录日志，人工排查 |

## 1. 模块一·会议纪要（Meetings）

### 1.1 接口清单

| 接口 | 通道 | 方法 | 路径 |
|---|---|---|---|
| 创建会议（音频） | Edge Function | POST | `/functions/v1/meeting-create-audio` |
| 创建会议（文本） | Edge Function | POST | `/functions/v1/meeting-create-text` |
| 查询任务进度 | SDK/轮询 | — | `select * from meetings where id=?` |
| 编辑条目 | SDK | — | `update meeting_items ...` |
| 导出 | 前端 | — | 客户端生成 MD/CSV |

### 1.2 POST `/functions/v1/meeting-create-audio`

**用途**：音频上传后启动 fun-asr/Paraformer 转录 + Qwen 结构化提取（异步）。

**请求**（`multipart/form-data`）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `project_id` | uuid | 是 | 项目 ID |
| `title` | string | 是 | 会议标题 |
| `file` | binary | 是 | 音频文件，mp3/wav/m4a，≤50MB |
| `language` | string | 否 | 默认 `zh`（fun-asr 中文优先） |

**处理流程**（Edge Function 内）：
1. 校验鉴权 + 文件体积/格式
2. 上传音频到 Storage `meeting-audio/<user_id>/<meeting_id>.<ext>`
3. 建库 `meetings` 记录，status=`uploading` → `transcribing`
4. 调 fun-asr/Paraformer **异步转写**：提交转写任务→回写 `asr_task_id`→轮询任务状态→取结果写 `raw_text`，status=`analyzing`
5. 调 Qwen-Max 结构化提取（Prompt 见 §1.5），批量 insert `meeting_items`（含 quote/quote_offset），写 `summary`
6. status=`completed` + `completed_at`，写 `llm_usage`，返回结果

**响应**（`success=true`）：
```json
{
  "success": true,
  "data": {
    "meeting_id": "uuid",
    "status": "completed",
    "summary": "本次会议围绕...",
    "items": [
      {
        "id": "uuid",
        "category": "decision",
        "content": "决定下周上线支付模块",
        "assignee": "张三",
        "priority": "high",
        "quote": "下周一定要把支付上了",
        "quote_offset": 1234
      }
    ],
    "llm_usage": { "asr": { "task_id": "...", "duration_sec": 180 }, "llm": { "model": "qwen-max", "tokens": 1850 } }
  }
}
```

> **CP0：转写为异步任务**。Paraformer/fun-asr 是"提交任务→轮询状态→取结果"（不同于 Whisper 的调用即返回）：
> - Edge Function 提交转写任务后落 `asr_task_id`，status 停在 `transcribing`；
> - **超时落 failed（A2.3）**：若转写任务超时（如 5 分钟无进展）或 Edge Function 超时被杀，自动置 status=`failed`，前端展示重试；
> - 前端轮询 `meetings` 表 status；`completed` 后取结构化结果。
> - **超时降级**：受 Edge Function 单次执行时长（默认 150s）限制，若一轮内未完成，返回 `status: transcribing` + `asr_task_id`，前端继续轮询（可断点续查）。

### 1.3 POST `/functions/v1/meeting-create-text`

**请求**（JSON）：
```json
{
  "project_id": "uuid",
  "title": "周会纪要",
  "raw_text": "粘贴的会议笔记全文..."
}
```
**处理**：跳过转写，直接 Qwen-Max 结构化提取，其余同 §1.2。

### 1.4 状态机（会议模块）

```
              ┌──────────────────────────────────────────────────────┐
              ▼                                                      │ 重试
[uploading] ──► [transcribing] ──► [analyzing] ──► [completed]
   │ (仅audio)     │                  │
   │               │ 文件/fun-asr失败  │ Qwen 失败     │ 超时(僵尸态)
   │               │  或任务超时       │               │(5min无更新)
   └───────────────►──────────────────► [failed] ◄────┘ ──► (用户重试 → 回到 uploading)
```

| 状态 | 触发 | 前端展示 |
|---|---|---|
| `uploading` | 创建/重试 | "上传中…" 进度条 |
| `transcribing` | fun-asr/Paraformer 提交任务 | "转录中…预计 1-2 分钟" |
| `analyzing` | 转录完成，Qwen-Max 开始 | "AI 正在提取决策与待办…" |
| `completed` | 全部完成 | 展示四类条目 + 摘要 |
| `failed` | 任一环节失败 / **超时僵尸态（A2.3：transcribing/analyzing 超 5min 无更新自动落 failed）** | 红色提示 + 重试按钮（带 error_message） |

### 1.5 Qwen-Max 结构化提取 Prompt 契约（输出 JSON Schema）

> Edge Function 用 DashScope OpenAI 兼容接口 + `response_format: { type: "json_object" }` 强制 JSON（Qwen-Max/Plus 支持；prompt 内也须写明"仅输出 JSON"双重保险）。Prompt 中文（需求清单 §7 国际化）。

**期望输出**：
```json
{
  "summary": "整体摘要（2-4 句）",
  "items": [
    {
      "category": "decision | todo | requirement | issue",
      "content": "条目内容（简洁陈述）",
      "assignee": "负责人姓名或 null（无明确则 null）",
      "priority": "high | medium | low",
      "quote": "原文中支撑该条目的原话（必须逐字来自输入文本）"
    }
  ]
}
```
**Edge Function 后处理**：
- 对每条 `quote` 在 `raw_text` 中查找字符偏移，写入 `quote_offset`；找不到则 `quote_offset=null` 且记日志（影响"原文引用可追溯率"验收）。
- `assignee=null` 时前端展示"待分配"。

## 2. 模块二·API 设计器（API Designer）

### 2.1 接口清单

| 接口 | 通道 | 方法 | 路径 |
|---|---|---|---|
| 生成 OpenAPI | Edge Function | POST | `/functions/v1/api-generate` |
| 保存版本 | SDK | — | `insert into api_versions ...` |
| 校验 YAML | 前端 +（可选）Edge | — | 客户端 yaml + swagger-parser |
| 导出 | 前端 | — | 客户端生成 yaml/json |

### 2.2 POST `/functions/v1/api-generate`

**请求**（JSON）：
```json
{
  "project_id": "uuid",
  "draft_id": "uuid",
  "title": "用户登录接口设计",
  "business_requirement": "实现邮箱+密码登录，返回 JWT...",
  "api_spec_context": "团队规范：统一 camelCase，错误码用 {code,message,data}...",
  "regenerate": false
}
```

**处理流程**：
1. 校验鉴权 + `business_requirement` 非空
2. `api_spec_context` 缺省取 `projects.api_spec_context`
3. 建/更新 `api_drafts` 记录，status=`generating`
4. 调 Qwen-Max 生成 OpenAPI 3.0 YAML（Prompt 强制 camelCase + 含 400/401/404/500）
5. **服务端用 swagger-parser 校验 YAML 合法性**（验收门槛 100%），非法则重试一次，仍非法则 status=`failed`
6. 写 `current_yaml`，insert `api_versions`，更新 `current_version_id`
7. status=`completed`，返回

**响应**：
```json
{
  "success": true,
  "data": {
    "draft_id": "uuid",
    "version_id": "uuid",
    "version_number": 1,
    "yaml": "openapi: 3.0.0\n...",
    "validation": { "valid": true, "errors": [] },
    "llm_usage": { "llm": { "model": "qwen-max", "tokens": 2100 } }
  }
}
```

### 2.3 状态机（API 模块，简化版）

```
[generating] ──► [completed]
     │
     │ Qwen 失败 / YAML 非法（重试后仍非法）
     └─► [failed] ──► 重试 → [generating]
```

### 2.4 Qwen-Max 生成 Prompt 契约

**强制约束**（写入 system prompt）：
- 输出 **OpenAPI 3.0** 合法 YAML
- 字段命名 **camelCase**
- 每个 path 至少包含 `400/401/404/500` 四个错误响应
- 包含 `components/schemas`
- 遵循用户提供的 `api_spec_context`（若有）

**Edge Function 后处理**：
- 程序化扫描所有 schema 字段名，校验 camelCase（不合规字段计入"字段命名规范率"）
- 校验每个 path 含齐四个错误码（计入"错误码完整率"）

### 3.2 POST `/functions/v1/feedback-analyze`

**请求**（JSON，两种输入二选一）：
```json
{
  "project_id": "uuid",
  "title": "7 月用户反馈",
  "input_mode": "paste",                 // paste | file
  "feedback_column": null,               // file+CSV 时必填，指定反馈列名
  "feedback_items": [                    // paste 模式：数组
    "登录总是失败，很烦",
    "界面很好看，点赞"
  ],
  "file_path": null                      // file 模式：Storage 路径
}
```

**处理流程**：
1. 校验鉴权；file 模式从 Storage 拉取并按 `feedback_column` 解析
2. 建 `feedback_analyses`，total_count=条目数，status=`uploading`→`analyzing`
3. 批量 insert `feedback_items`（此时无 topic_id）
4. 调 Qwen-Plus 聚类（Prompt 见 §3.5），返回 topics + 每条反馈归属
5. insert `feedback_topics`，update `feedback_items.topic_id` + `sentiment`（触发器自动同步 `frequency`）
6. status=`completed`，返回

**响应**：
```json
{
  "success": true,
  "data": {
    "analysis_id": "uuid",
    "stats": {
      "total": 120,
      "topic_count": 8,
      "high_priority_count": 3,
      "negative_ratio": 0.35
    },
    "topics": [
      {
        "id": "uuid",
        "name": "登录问题",
        "summary": "集中在登录失败与验证码收不到",
        "frequency": 32,
        "sentiment": "negative",
        "priority": "high",
        "sample_feedback": ["登录总是失败", "验证码收不到"]
      }
    ]
  }
}
```

### 3.5 Qwen-Plus 聚类 Prompt 契约

## 5. SDK 直连操作（RLS 保护，无需 Edge Function）

> 前端用 `supabase.from('table').select/insert/update/delete()`，RLS 自动限定本人。以下列出关键操作契约。

### 5.1 项目

| 操作 | SDK 调用 |
|---|---|
| 列表 | `.from('projects').select('*').is('archived_at', null).order('created_at',{ascending:false})` |
| 创建 | `.from('projects').insert({ user_id, name, description, api_spec_context })` |
| 更新 | `.from('projects').update({ name, ... }).eq('id', id)` |
| 归档 | `.from('projects').update({ archived_at: now() }).eq('id', id)` |

> `user_id` 由前端从 session 取，但 RLS 的 `with check` 会强制等于 `auth.uid()`，故无法伪造。

### 5.2 会议条目编辑（支撑"未编辑率"指标）

```js
// 编辑条目（触发 trg_mark_meeting_edited 自动置 meetings.is_edited=true）
await supabase.from('meeting_items')
  .update({ content, assignee, priority, is_edited: true })
  .eq('id', itemId);

// 手动新增
await supabase.from('meeting_items')
  .insert({ meeting_id, user_id, category, content, is_manual: true });
```

### 5.3 反馈主题合并/删除

```js
// 合并：把 B 主题下所有 feedback_items 的 topic_id 改为 A，再删 B（frequency 由触发器同步）
await supabase.from('feedback_items').update({ topic_id: topicAId }).eq('topic_id', topicBId);
await supabase.from('feedback_topics').delete().eq('id', topicBId);

// 删除主题：feedback_items.topic_id 置 null（on delete set null），主题记录删除
await supabase.from('feedback_topics').delete().eq('id', topicId);
```

### 5.4 API 版本管理

```js
// 保存当前编辑为新版本
const { data: v } = await supabase.from('api_versions')
  .insert({ draft_id, user_id, version_number: nextNum, yaml_content, is_auto: false });
// 更新当前指针
await supabase.from('api_drafts').update({ current_version_id: v.id, current_yaml: yaml }).eq('id', draftId);
```

## 6. 上传流程（Storage 签名 URL）

### 6.1 音频上传（模块一）

```js
const path = `${user.id}/${meetingId}.${ext}`;
const { data, error } = await supabase.storage
  .from('meeting-audio')
  .upload(path, file, { contentType: file.type, upsert: false });
// 之后调 Edge Function，传 path 而非文件（避免 Edge Function 二次上传）
```

> **两种上传方案**（开发时择一）：
> - **方案 A（推荐）**：前端直传 Storage → 把 `path` 传给 Edge Function → Edge Function 从 Storage 拉。降低 Edge Function 体积压力。
> - **方案 B**：前端把文件 multipart 传给 Edge Function → Edge Function 上传 Storage。简单但 Edge Function 负载高。

v1 选 **方案 A**（音频可能近 50MB，避免 Edge Function 中转）。
